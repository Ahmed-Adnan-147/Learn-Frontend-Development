   -> How does max-width solves Overflow issues?
   -> The difference b/w width & max-width is that , when you give width to the element, and then 
      reduce the element viewport from the given width, the element will be overflow and the 
	  scroller will be added, but whereas, in max-width the overflow will not happen, when we
	  reduce the viewport, the width of the element will also decrease at the same time.
	  By default, the element width will be 100% of the viewport.
   ---------------------------------------------------------------------------------------------
   * Understand Width & Height in Percentage:
     -> Whenever we give width in % percentage, it will take the width of its parent and then
	    decide what width to be applied.
	 -> But the height in % doesn't work, we need to apply height in pixels. It will work only if
	    u give the absolute units.
     -> when we apply height to the child element in absolute units, it will also affect the
	    parents heights, it will also gets changed.

   ---------------------------------------------------------------------------------------------
   * Experiment with Padding in Pixel vs Padding in Percentage:
     -> You can apply padding in % as well, again it will calculate according to its parent element
	 -> But the main element width size gets changed, so we apply border-box:box-sizing; to it.
	 -> When we give padding in %, it will calculate from its parent.
	 -> Margin also works the same way, but the border doesn't work. Border will display as invalid
	    property.
	
   ---------------------------------------------------------------------------------------------
   * Experiment with font-size:
     -> The original font-size will be 16px which is 1em, you can look this in Computed of the 
	    selected element and then check the Show all filter and can see it.
	 -> So, when we give 200% font-size to the element, then it will be 32 px.
	 
   ---------------------------------------------------------------------------------------------
   * Understand Viewport Width in Depth:
     -> the width will be taken from viewport, it means the browsers width will be taken and 
	    calculated. It doesn't take from body or html element, it takes the browsers viewport i.e,
		the laptop or desktop full screen width will be considered as viewport.
	 -> You can check the browsers viewport by going to mobile responsive in dev tools, that will
	    be the exact viewport of the browser, and you can check there by giving the body width as
		600px, then also the element width will not be 300, instead it will take from the browsers
		viewport.
		
   ---------------------------------------------------------------------------------------------
   * MAIN POINTS TO REMEMBER:
     -> When we apply % to the width, it will take the parents width from there it will set.
	 -> If u try to give % in height, it won't apply, even if it is a block level element, bcoz,
	    the height should be given in pixels, not in %.
	 -> when we apply height to the child element in absolute units, it will also affect the
	    parents heights, it will also gets changed.
	 -> Never ever give margin & padding in %, it creates so many issues.
	 -> Best Practice is not to give height to the elements, as the height will be handled by the 
	    browser accurately.
